# LS7A2000 显示硬件契约

本文限定 [hardware/ls7a2000.h](../hardware/ls7a2000.h) 后端的职责。新实现硬件依据是《龙芯7A2000独显桥片用户手册 V1.3》；通用 DRM/TTM API 规定软件对象语义。旧 Loongson/i915 源码只用于 [来源核对](source-provenance.md)，不用于填补硬件手册缺口。

本地实验资料：[手册摘录与缺口记录](../../../evidence/2026-10-04/graphic-rewrite/manual-display-spec.md)、[PDF](../../../docs/manuals/LS7A2000-user-manual-v1.3.pdf)。这些相对路径对应实验工作区，不是驱动编译依赖；单独分发源码时，可凭文件名和以下校验值识别手册。

- 文件名：`LS7A2000-user-manual-v1.3.pdf`，224 页。
- SHA256：`ed310fec83341ca1de5ee0cb0d47f34e47e12d80ecf7989d5d662f362edc0764`。
- 页码用纸面页脚 `pN`；对应从 1 开始的 PDF 第 `N+17` 页，例如 p157 为 PDF174。

以下明确区分 **手册规定**、**初版软件约束** 和 **工程策略/观察**。新架构已通过目标编译和实机测试，范围见 [验证记录](validation.md)。

## 1. 设备与地址空间

| 项目 | 契约 | 手册出处 |
| --- | --- | --- |
| DC | D6:F1，VID `0x0014`、DID `0x7a36`；由本模块绑定 | §3.1.1 p14–15，§20.1 p157 |
| 配对 GPU/显存 | D6:F0、DID `0x7a25`，GMEM BAR 位于 PCI BAR2/3；只取得所需显存所有权，不实现 GPU 执行单元 | §19.1 p145，§3.1.3 p18 |
| DC 窗口 | BAR 对应 64 KiB；控制寄存器按 32 位字访问 | §3.1.3 p17，§20.1 p157–158 |
| 桥片配置窗口 | 独立于 DC BAR 和 PCI 配置空间；基址由 BIOS 配置 | §3.1.3 p17，§4 p20 |
| 输出范围 | 两路 HDMI，HDMI0 与 VGA 显示内容相同；标称每路最高 1920×1080@60 | 第20章 p157 |

`bridge_base=0x10010000` 是本实验板的既有配置，手册也将其列作地址分配示例；它不是所有机器通用的发现规则。root 设备层映射窗口，只有 hardware 层读写控制寄存器。桥片共享 GPU/显存/图形核心时钟不因调整某个输出而获得修改授权。

CPU resource 地址和 PCI bus 扫描地址分别保存。memory 根据 PCI 资源和 BO 在 VRAM 的位置提供 bus 地址，display 检查 plane 子区间。禁止把 CPU 地址直接截成低 32 位作为扫描地址。p18 表3-4 的窗口 mask 语义存在未解释处，不能凭经验把印刷公式改为另一种转换公式。

## 2. 主平面与双缓冲

| 内容 | 手册规定 | 初版软件约束 |
| --- | --- | --- |
| 格式 | §20.2.1 p158 的 Format=4 为 ARGB8888 | 主平面只接受线性 XRGB8888 的既定映射；字节序/颜色需实机观察，不承诺所有手册枚举 |
| 行跨度 | §20.2.8 p160：stride 按 256 字节向上取整 | dumb pitch 与 plane 检查均遵守 256；这不自动等于 BO 基地址对齐规则 |
| 主 FB 地址 | §20.2.2/.3 p158–159 只列 `[31:0]` | 整个可扫描地址区间必须落在 32 位 PCI bus 范围；不写未记载的主 FB 高位寄存器 |
| Meta 地址 | §20.2.4–.7 p159–160 独立描述 Meta0/1 低高地址 | 不将 Meta 高位解释为线性 framebuffer 高位 |
| 切换 | §20.2.1 p158：bit7 请求下一帧切换，bit11 为只读当前 bank | 一路只推进受串行化的事务；display 等待新帧及目标 bank 后再退休旧 BO |
| 原点 | §20.2.9 p160 建议一般为0 | 由已检查的扫描地址/pitch 表达取数计划，后端使用既定 origin 策略 |

plane 在写地址前已经持有 BO pin，并检查 offset、最后一行、pitch、像素字节数和加法溢出。后端发布地址和扫描开关时处理写入次序。手册没有给切换队列、所有锁存点和 DMA-idle 位，不能由“下一帧切换”推导出任意并发更新都安全。

## 3. 模式和像素 PLL 继承

时序出处为 §20.2.13–.19 p161–163；PIX PLL 公式和范围为 §2.2.1/.2 p9–11，桥片 PIX0/1 字段为 §4.9/.10 p31–32，本地 PIX 配置源选择为 §20.2.52/.53 p174–175。

手册给出的关系是：

```text
pixel_clock = 100 MHz / div_ref × loopc / div_out
20 MHz ≤ 100 MHz / div_ref ≤ 40 MHz
1.8 GHz ≤ 100 MHz / div_ref × loopc ≤ 4.8 GHz
```

继承快照要求除数非零、时钟选中且已锁定、未处于旁路/掉电等不支持状态；关闭输出的 DPMS 状态仍可能保留有效时序，不能仅因 enable 位为0拒绝捕获。快照可以来自固件，也可以来自此前软件留下的配置，变量名 `firmware` 不证明其最初配置者。

初版只发布捕获的一个模式，横纵活动区不超过 1920×1080，不合成新的像素频率。DRM mode 的时序和 flags 要匹配，`clock` 还要单独整数相等；generic `drm_mode_equal()` 的时钟周期取整不足以代表此处的严格相等。手册同步极性只描述“取反”，没有正负基准；后端保持既有反转位，不猜正/负同步标志。

旧基线采集的 pipe1 参数为 `div_ref=3, loopc=49, div_out=11`，像素时钟约 148484.85 kHz，接口取整为 **148485 kHz**。其 VCO 约 **1633.33 MHz**，低于手册下限。当前策略允许继承已锁定的这组参数，通过 `pll_out_of_spec` 向上层报告并打印 warning；这是明确的保留策略，不是该参数合法性或长期稳定性的证明，也不用于生成新的参数组合。

桥片 PLL 跨32位字段用分开的字访问，不因为字段宽度为64位就使用未确认的 `readq()`。保存除数供诊断，不提供像素 PLL 重配接口。

## 4. HDMI PHY、HPD 与 DDC 缺口

| 内容 | 手册出处和已知信息 | 当前处理 |
| --- | --- | --- |
| HDMI 数字接口 | §20.2.32/.33 p167：接口、包、音频、DDC pad 等字段分别存在 | 继承板端控制位并恢复显示使能，不宣告音频已实现 |
| PHY | §20.2.40 p170：enable、低有效 reset、板级 bias/term 字段；enable 低脉冲至少1µs | 保留板级参数，只执行已定义的使能/复位操作 |
| PHY PLL | §20.2.41 p170：IDF/NDIV/ODF、enable、lock、调试旁路字段 | 保留继承配置；不套用像素 PLL 的公式、不猜 ODF 编码或 TMDS 调参表 |
| HPD | §20.2.55 p175：`0x1ba0` bit0/1 为 HDMI0/1 插入状态 | connector 通过后端读状态并 polling |
| DDC/EDID | §20.2.33 p167 只明确 GPIO/内置I2C选择；缺 GPIO位号、控制器基址、端口对应关系 | 不凭任意 I2C 控制器补 EDID；无 EDID 时仅发布继承模式 |

手册没有 PHY PLL 的完整频率关系、模拟参数推荐表、最大锁定时间。实现中的 lock 等待上限属于工程超时。第11章的六路 MISC I2C 没有被手册对应到 HDMI DDC，不能直接拿来替代。

## 5. 光标

§20.2.22–.31 p164–167 给出两路 cursor 的独立寄存器组、32/64尺寸、ARGB8888、热点和位置。两路寄存器不是统一固定 stride 复制；位置为 Y 高12位、X 低12位，和扫描位置寄存器的 X/Y 排列不同。

初版接口只支持打包 **64×64 ARGB8888、pitch=256**，不宣称 32×32 的行布局已解决。公开后端地址参数保守使用32位；手册给 cursor 高位字段不等于任意64位 DMA 地址都有效。

部分屏幕外位置使用热点与位置组合，是需要验证的实现策略；完全不可见的光标应隐藏，不能把负坐标直接当无符号12位写入。手册没有完整描述负坐标裁剪、Alpha 预乘方式及精确混合舍入。视觉检查应覆盖边缘、透明像素和颜色，ioctl 成功不足以证明这些效果。

光标更换 BO 与移动位置也处在显示事务中。尤其是没有用户 event 的 BO 更新，旧 pin 仍须等待完成边界；不能因 cursor 小就省掉退休协议。

## 6. IRQ、W1C 与软件完成

§20.2.60 p177–178 的 `Interrupt 0x1570` 把低16位 W1C 状态与高16位 enable 放在同一个32位字。VSYNC1 对应低 bit0，VSYNC0 对应低 bit2；使能分别位于状态位加16的位置。

后端用 `irq_mask` 加 `irq_lock` 保存和串行化使能状态，确认时只写需要清除的已识别状态位。禁止把整个读回字当普通读改写值，否则会顺便清掉无意处理的 W1C 状态。上层只接收 `BIT(pipe)`，无需了解硬件位号。

Vsync counter 为 §20.2.51 p174 的只读32位字段。counter、VSYNC IRQ、FBReadEnd 和 bank切换不是同一个事件。display 的事务完成把所需观察条件明确组合；用户 event 可以没有，completion 不可以省略。counter 溢出和关闭输出时的行为不能从字段宽度之外补造承诺。

## 7. 停止与帧时间排空

手册说明输出开关和下一帧切换，但未给 DMA 停止完成位或完整停止等待流程。后端的当前工程策略是：关闭 cursor 和扫描切换/输出，读回控制寄存器，然后按捕获模式等待一个完整帧周期再加1ms余量，最后关闭数字链路。

```text
frame_us = ceil(htotal × vtotal × 1000 / clock_khz)
```

休眠范围另外保留调度余量；无有效 timing 时回退帧周期为20ms，再加上述1ms。capture 拒绝超过1秒的帧周期，使有模式的排空等待有明确上界。具体实现在 `ls7a2000_pipe_disable()`，可以睡眠，只能在进程上下文调用。

首次接管也先捕获、停止并排空 firmware 扫描，然后才允许显示 BO 分配。若仍在运行的 pipe 没有可接受的捕获模式，初始化会拒绝接管，避免以未知帧周期推进正常分配。

这是 **frame-based drain 工程策略**，不是手册保证的 DMA-idle completion。正常完成使用 IRQ/目标 bank；timeout/cancel 则先停止并执行此策略，再终结软件事务和允许旧 BO 退休。新架构须单独验证这些路径，不能把旧版本固定20ms等待的记录直接搬作证明。

## 8. 下一步扩展需要的新证据

| 扩展 | 首先需要补齐的证据 |
| --- | --- |
| 任意模式/刷新率 | PHY PLL 输入/编码/频率关系、板级参数和模式验证；不能只补像素 PLL 求解器 |
| EDID/DDC | 引脚及控制器映射、事务与恢复方法 |
| 更宽主扫描地址 | 官方主 FB 高位接口或可复现的独立实验；Meta 不能冒充 |
| 32×32 cursor/更多 Alpha 能力 | 实际行布局、混合规则和视觉用例 |
| 严格 DMA 排空 | 官方 idle/completion 机制或有边界的硬件实验 |
| GPU 2D/3D 加速 | GPU 执行单元自己的编程接口；DC 扫描输出手册不提供命令提交能力 |

所有扩展仍需标明手册规定、实验观察和工程选择。可学习的资源/KMS/事务架构已经明确，并不使缺失的硬件资料自动补齐。

## 本机坐标生效边界

当前模式实验：同图像 Move ioctl 约7µs返回，位置在下一次 VSYNC 读到新值；300笔连续请求合并到下一帧末笔位置。这是本次观察，不是手册对所有模式的保证。readback 保证 MMIO 顺序，不能消除硬件内部帧锁存。新旧状态保护同一 BO 时，坐标提交可以立即完成；更换 BO 仍等待退休。
